# T4.4a - testes da mini-run

Novo: `tests/test_run.py` (50 testes). Escritos a partir do PLAN.md (Fase 4) e dos relatórios T4.1/T4.2; só API pública.

Cobertura: dados (schema, 6 camadas, chefe final, ids únicos, inimigo/tipo; `check_run` rejeita inimigo inexistente, camada final com 2 nós, start_deck != deck_size, tipo divergente, id repetido), `new_run` (12 adultos, seed, erros sem run.json / deck_size diferente), fluxo (camadas, nó ilegal, estados errados, draft de 3 distintos, elite com `draft_options_elite`, descanso, pick_draft, índice inválido, `nodes_cleared`, chefe sem draft, derrota, duelo recomeça do zero), serialização (round-trip JSON, mesma sequência de drafts, `to_dict` durante duelo, abandon) e propriedade (100 runs com IA em 0,7 s, 16 vitórias; determinismo por seed).

Resultado `pytest -q`: **1444 passed, 0 failed, 0 skipped, 0 xfail** (95 s).

Achados: nenhum bug no core.

Notas:
- Para testar só o fluxo da run, vários testes fixam `duel.winner` após `start_duel` (campo público do `Duel`). Duelos reais com IA são jogados no teste "recomeça do zero" e na propriedade.
- "Gato morto não volta ao duelo seguinte" é coberto indiretamente (cada duelo cria o deck de `deck_spec()` completo; checado por tamanho do `initial_deck` e Líder cheio).
- Elite com `draft_options_elite` diferente de 3 é testado com cópia do conteúdo em memória (`Content.run` mutável); se o `Content` virar imutável, ajustar.
