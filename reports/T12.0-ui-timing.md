# T12.0 - ui_timing.json (tempos de animação do duelo)

## O que mudou
- `data/ui_timing.json`: tempos e intensidades do polimento do duelo (segundos e pixels). Valores iniciais passados pelo orquestrador; `beats` copia o `_DUR` atual de `ui/controller.py` (mais `default` 0.3).
- `data/schemas/ui_timing.schema.json`: schema estrito (additionalProperties false em todos os blocos, números >= 0, `lunge.reach` em 0-1, `breathing.period` e multiplicadores de `enemy_speed` > 0, `poof.particles` e `damage_number.big_threshold` inteiros).
- `data/validate_data.py`: o arquivo já entra pelo glob; novo `check_ui_timing` confere que `enemy_speed.default` existe em `enemy_speed.options`.
- `data/schemas/examples/ui_timing.example.json` e 4 inválidos em `examples/invalid/` (negativo, reach > 1, chave extra, tipo errado), exigidos por `validate_examples.py`.

## Como validar
- `python data/validate_data.py` e `python data/schemas/validate_examples.py`
- `pytest -q`: 3051 passed.

## Pendências
- A interface ainda usa o `_DUR` hardcoded; ler `data/ui_timing.json` em `ui/` é outra tarefa (agente interface).
- `.venv` está sem pacotes (só pip, Python 3.14). Validei e rodei os testes com o Python do sistema. Alguém precisa rodar `pip install -r requirements.txt` no `.venv`.
- Sem dúvidas de design: nenhum número foi inventado.
