## Achados e solucoes dentro de `build/` (workarounds)
1. **Trap de WebAssembly** em `pygame._sdl2.video.Window.from_display_module()` (`ui/display.py:56`): "function signature mismatch", nao capturavel por `try/except`, congela o jogo na tela cinza. `build/web/main.py` injeta um modulo falso para esse import so no navegador.
2. **jsonschema** exige `rpds-py` (binario Rust, sem wheel wasm): `build/web/jsonschema.py` e um stub (validate = no-op) so no pacote web; PC usa o real. Os JSON continuam validados pelos testes.
3. **Prefs** estao fixos em `ROOT/saves` (`ui/audio.py:28`, default de `setup()`): em PC isso seria `<instalacao>/_internal/saves` (quebra em pasta somente-leitura). O launcher redireciona prefs e save para `%APPDATA%\Chaoscats` envolvendo `audio.setup`; no web, para `/data/data/chaoscats`.
4. **Save no navegador**: `/data` do pygbag NAO persistiu ao recarregar. `build/web/main.py` espelha `save.json`/`prefs.json` em `localStorage` (restaura no inicio, grava a cada ~1 s se mudou). Funcionou no teste.
5. pygbag so baixa o pygame-ce se `main.py` importar `pygame` no topo (feito).
